# paper-cover-letter

从论文材料撰写、修改和审核英文期刊投稿信的 Agent Skill。基于原有 cover letter 模板，保留“投稿意图 → 研究贡献 → 期刊契合 → 声明 → 联系方式”的顺序，增加事实依据与声明确认规则。

**模板不是作者确认。缺少发现就留待补充，未确认的投稿声明就不写成事实。**

## 文件与职责

```text
paper-cover-letter/
├── SKILL.md                         Agent 的触发条件与工作规则
├── assets/cover_letter_template.md   用户提供的英文原始模板
├── README.md                        使用说明与模板审核
└── tests/
    ├── cases.md                     可复用的行为测试提示与通过标准
    ├── validation.md                本次实际验证记录与局限
    └── observed/                    本次模拟测试的实际回复
```

仓库根目录就是 Skill 目录；引用资源使用相对路径。将整个目录交给支持 Agent Skills 的工具，按照该工具的技能安装方式加载。单独上传模板不会自动加载 `SKILL.md` 中的规则。尚未声称在所有 Agent 平台上完成兼容性测试。

也可直接向能读取本地文件的 Agent 指定：

> 请读取 paper-cover-letter/SKILL.md，并按照其中规则，使用我的材料撰写投稿信。

若使用环境支持 `$skill-name` 调用，可使用 `$paper-cover-letter`。本仓库不会自动安装技能、提交论文或发送邮件。

## 原模板与生成时的处理

`assets/cover_letter_template.md` 逐字保留用户提供的原文，包括方括号占位符、原有措辞与声明段，不在该文件中插入说明或改写。以下规则由 `SKILL.md` 在生成具体投稿信时应用；模板中的肯定句不代表用户已确认相关事实。

| 原模板要素 | 风险 | 生成投稿信时的处理 |
| --- | --- | --- |
| “to be published by” | 暗示将被录用 | 生成时优先采用 “for consideration … in”，原始模板保留原文。 |
| 固定 “original research paper” | 可能与实际文章类型不符；也不构成原创性确认 | 根据材料填写文章类型，原创性另行确认。 |
| “Studies have shown …” | 没有文献也容易补写背景主张 | 仅在材料支持时使用，不强制填满背景句。 |
| “we show … significant …” | 可能把相关性、贡献或差异夸大为因果、突破或统计显著 | 保留研究设计、数值、方向和适用范围；不自动添加“首次”“显著”。 |
| “aligns with the journal’s scope” | 可能只凭期刊名称编造契合理由 | 使用官方范围说明或用户提供的来源，未核验时明确标注。 |
| “has not been published elsewhere” | 用户未确认；预印本等情况需要具体处理 | 确认传播/发表历史及适用要求后再使用准确表述。 |
| “None of the authors have any conflicts …” | 模板不能代表全体作者作出声明 | 分别确认声明内容及作者范围；已知利益冲突如实披露。 |
| 编辑姓名、地址、署名 | 容易为了完整而编造 | 无编辑姓名可用 “Dear Editor,”；不必要字段省略。 |

## 如何提供材料

可以先提供摘要或简短研究说明，不必一次提交完整稿件。建议包含：

- 论文标题、文章类型、目标期刊；
- 研究问题、设计/方法、核心发现与贡献（有原始数值则保留）；
- 期刊官方范围/作者指南链接或原文摘录；无法提供时允许生成带说明的初稿；
- 通讯作者姓名、单位和邮箱（可暂用占位符）；
- 已确认的投稿声明及其范围；不知道的项目直接写“未知”。

声明按项记录，不能互相推导：原创性、既往发表或传播、未在其他期刊审理、全体作者同意、利益冲突，以及适用的伦理/资助等信息。例如，“尚未发表”不等于“未同时投稿”，“我无利益冲突”不等于“全体作者无利益冲突”。已经明确确认的同一稿件事实无需反复询问。

有预印本、会议材料或相关稿件时，应提供具体情况；本 Skill 不会自动判断它们构成违规，也不会用笼统的“未发表”掩盖已知情况。期刊要求某项声明，不代表作者已经满足该要求。

## 输出约定

输出一封可复制的英文信件，并在信件外用用户的语言列出必要的待补事项、冲突和来源说明。信息不足时明确标为初稿；原始模板保留 `[字段说明]` 格式，生成草稿可用方括号或 `{{FIELD_NAME}}` 等清晰占位符，不冒充已经完成的内容。只有材料支持且已获相应确认的声明才会进入正文。

通常保持简洁，250–400 词只是写作偏好；用户要求及已核验的期刊要求优先。不会为了凑字数补造结果。若无法访问期刊官网，只说明使用了用户提供的材料或尚未核验，不能声称已查阅。

## 测试与维护

见 [行为测试案例](tests/cases.md) 和 [实际验证记录](tests/validation.md)。用例以可观察行为评分，不要求完全相同的英语措辞。每次修改后，应检查入口元数据、相对链接、模板占位符及关键行为；格式校验通过不等于不存在学术事实错误。

测试只使用明确标为虚构的材料，不应将未发表的真实稿件、作者联系方式或测试过程中的私人内容提交到公开仓库。外部上传、发信及投稿需要各自的用户授权。
